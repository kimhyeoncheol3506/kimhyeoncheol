# 페이스리스 경제채널 분석실

국내 페이스리스(얼굴 비공개) 경제·재테크 유튜브 채널의 최근 바이럴 영상을 수집·분석하고, 그 결과를 **내 채널의 첫 영상 기획·대본·30일 일정**으로 바꿔 주는 로컬 웹 애플리케이션입니다.

> 이 폴더는 저장소 루트의 사주·관상 앱과 **완전히 분리된 별도 프로젝트**입니다. 루트 앱의 파일은 건드리지 않았고, 루트 `tsconfig.json`의 `exclude`에 이 폴더만 추가했습니다.

## 1. 설치 및 실행

Node.js 18.18 이상(권장 20 또는 22)이 필요합니다.

```bash
cd faceless-econ
npm install
npm run dev          # http://localhost:3100
```

- 테스트: `npm test` (점수 계산·결측 처리·14일 필터·CSV·모의 API 수집 35개)
- 타입 검사: `npm run typecheck`
- 운영 빌드: `npm run build && npm start`
- 터미널에서 수집만 실행: `npm run collect` (Windows 작업 스케줄러 등으로 하루 1회 실행 권장)

API 키가 없으면 **데모 모드**로 모든 화면이 동작합니다. 화면 상단이 노란 띠(데모)인지 초록 띠(실제)인지로 구분됩니다.

## 2. YouTube API 키 설정

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트 생성
2. **API 및 서비스 → 라이브러리 → YouTube Data API v3 → 사용**
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키** (키 제한에서 YouTube Data API v3만 허용 권장)
4. `faceless-econ/.env.example`을 `.env.local`로 복사하고 `YOUTUBE_API_KEY=` 뒤에 키 붙여넣기
5. `npm run dev`를 껐다가 다시 실행

`.env.local`과 `data/`(수집 데이터)는 `.gitignore`로 Git에서 제외됩니다. 키는 서버에서만 읽으며 화면·로그·캐시·내보내기 파일에 기록되지 않습니다(테스트로 확인).

## 3. 실제 데이터를 수집하고 상위 3개를 확정하는 방법

1. **G. 데이터 및 설정 → 지금 데이터 수집 실행** (1회 약 50~150단위, 일일 기본 할당량 10,000)
2. **매일 비슷한 시각에 다시 수집**합니다. 스냅샷이 쌓여야 `채널 내 상대 성과`와 `게시 후 24시간/72시간/7일/14일` 비교가 계산됩니다. 첫 수집만으로는 해당 지표가 '관측 부족'으로 표시되고, 나머지 지표의 가중치가 재조정됩니다.
3. **정밀 분석 대상 3개**: 첨부 자료에서 고른 `경제의 시작`, `재테크읽어주는 파일럿`이 고정되어 있습니다. 3번째 `경제·기업사 애니메이션 채널`은 아직 미확정이므로 후보(머니코믹스·만화 경제학·지식한입·경제스토리)의 영상을 직접 확인한 뒤 설정 화면에서 지정하세요. 대시보드에 데이터 기준 '자동 상위 3개'도 함께 표시되니 비교해 보세요.
4. **D. 영상 정밀 분석**에서 각 채널 상위 영상 3개를 실제로 시청하고 썸네일·도입부·시각 방식을 입력합니다. 직접 확인한 항목만 '관측'으로 바뀌고 E 화면의 패턴 분석에 반영됩니다.
5. 페이스리스 여부를 영상으로 확인했다면 **설정 → 페이스리스 수동 판정**에서 '확정'으로 저장합니다(파일럿 채널은 얼굴 비노출 영상만 영상 단위로 확정).

## 4. 화면 구성

| 페이지 | 내용 |
|---|---|
| A. 요약 대시보드 | 수집 채널·최근 14일 영상 수, 롱폼/쇼츠 바이럴 상위, 상위 3개 채널, 수집 시각, 결측 현황 |
| B. 채널 탐색 | 후보 채널 카드 10개(첨부 자료 형식), 채널별 구독자·분류·평균/중앙 조회수·점수, 초기/교체 후보와 선정·제외 사유 |
| C. 바이럴 랭킹 | 롱폼·쇼츠·기타 분리 순위, 시간당 조회수, 구독자 대비, 채널 내 상대, 좋아요율·댓글률, 경과 시간, 24h/72h/7d/14d 기준 정렬 |
| D. 영상 정밀 분석 | 영상 정보, 점수 산출 내역(원본·정규화·사용 가중치), 스냅샷 차트, 제목 분석, 관측/가설/검증되지 않음 구분, 직접 확인 입력, 원본 링크 |
| E. 상위 3개 비교 | 채널별 패턴, 주제·제목·길이 비교, 9개 질문에 대한 결론(근거 영상·표본 수·신뢰 수준·대안 가설), 따라 할/피할 요소 |
| F. 내 첫 영상 제작 | 6개 영역 평가, 후보 10개, 최종 추천, 도입 30초·전체 대본, 장면 구성표, 썸네일, 설명란·출처, 30일 일정(지연 시 우선순위 자동 조정) |
| G. 데이터 및 설정 | API 상태, 수집 실행·기록, 가중치·기간·데이터 모드, 상위 3개 지정, 페이스리스 수동 판정, 채널 추가·교체 후보 검색, CSV/JSON 내보내기, 데이터 한계 |

## 5. 점수 계산 (lib/scoring/viral.ts)

- **바이럴 성과 점수**: 시간당 조회수 30 · 채널 내 상대 성과 25 · 구독자 대비 조회수 20 · 좋아요율 10 · 댓글률 5 (설정에서 변경)
- **정규화**: 같은 형식(롱폼/쇼츠/기타) 그룹 안의 백분위 순위(0~100, 동점 평균)
- **결측 처리**: 0점으로 처리하지 않고 해당 지표를 제외한 뒤 가중치를 재조정. 관측 가능한 가중치가 50% 미만이거나 그룹이 3개 미만이면 **판정 보류**
- **채널 내 상대 성과**: 같은 채널·형식, 최근 90일 영상 중 경과 시간이 1/1.5~1.5배인 스냅샷의 시간당 조회수 중앙값 대비. 비교 영상 3개 미만이면 미계산
- **페이스리스 제작 적합성 점수**(별도): A 100 · C 95 · B 85 · E 50 · D 0 · U 결측
- **최종 벤치마킹 우선순위**: 두 점수를 마지막에만 가중 결합(기본 90:10)
- 게시 24시간 미만 영상에는 변동성 경고, 스냅샷이 없는 시점의 조회수는 역산하지 않음

## 6. 실제 데이터와 데모 데이터의 구분

- 데모 데이터는 `[데모]`가 붙은 **가상 채널**만 사용합니다(실존 채널명에 가짜 수치를 붙이지 않음).
- 화면 상단 띠 색(노랑=데모, 초록=실제), 모든 표의 출처 배지, CSV `데이터출처` 열, 내보내기 파일명 `DEMO_` 접두어로 구분합니다.
- 실제 데이터가 하나라도 수집되면 자동으로 실제 데이터만 표시하며, 두 데이터는 섞지 않습니다.

## 7. 구현 메모와 한계

- **저장소**: SQLite+Prisma 대신 JSON 파일(`data/store.json`)을 사용합니다. Prisma 엔진 다운로드나 네이티브 모듈 빌드가 Windows 초보 환경에서 설치 실패를 일으킬 수 있고, 이 규모(채널 15개·영상 수천 개)는 파일 저장으로 충분하기 때문입니다. 영상은 ID 키로 중복 없이 저장하고, 스냅샷은 (영상 ID, 수집 시각)으로 중복을 막으며, 쓰기는 원자적(임시 파일→rename)입니다.
- 썸네일 이미지·영상 화면·자막의 **자동 분석은 하지 않습니다**. 이미지를 상상해 분석하지 않도록 직접 확인 입력 방식으로 설계했습니다.
- 채널 후보 ID는 2026-10-11 YouTube 공개 검색 페이지에서 확인했습니다. 사전 페이스리스 분류는 모두 '추정'입니다.
- 첫 영상 대본의 최신 수치(기준금리·COFIX 등)는 지어내지 않고 `【확인 필요】`로 비워 두었습니다. 녹음 전 공식 사이트에서 확인해 기준일과 함께 기입하세요.
- 영상 다운로드, 비공개 자막 접근, 타 채널 대본·썸네일 복제 기능은 의도적으로 제공하지 않습니다.
