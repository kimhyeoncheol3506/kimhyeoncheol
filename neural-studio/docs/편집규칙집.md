# 편집규칙집 v0 — 얼굴없는 지식 설명 채널 (동그라미 캐릭터형)

> **중요 — 이 문서의 상태**
> 이 v0은 참고영상 4편(`_DTI05Ww8gQ`, `xRHj3FhG_NI`, `sUZZ7KAbnEQ`, `kwnzeZXlN3U`)을 **직접 보지 못하고** 만들었습니다.
> 작업 환경의 네트워크 정책이 youtube.com을 막고 있어서 내려받을 수 없었습니다.
> 그래서 아래 규칙은 요청하신 스타일 요소(음성 더빙, 자막 위치·폰트·강조, 모션, 동그라미 사람 캐릭터)와
> 한국 얼굴없는 지식·설명 채널의 일반적인 편집 문법을 바탕으로 만든 **초안**입니다.
> 영상을 확보하면 `python analyze_reference.py <영상들> --apply` 한 줄로 실측값(컷 간격, 자막 위치·크기·강조색,
> 배경음 레벨, 음량)을 재고, 그 값으로 `style.yaml`이 자동으로 바뀝니다. ⟨실측⟩이라고 표시한 항목이 측정해서 바꿀 값입니다.

이 문서는 사람이 읽는 규칙입니다. 같은 내용을 기계가 읽는 버전은 `style.yaml`이고, 그걸 실행하는 엔진은 `facetube/`입니다.

## 1. 포맷 한 줄 요약
흰 동그라미 머리에 콩 모양 몸통을 가진 막대인간 캐릭터가 파스텔 단색 배경에서 말하고 반응합니다.
이것을 남성 내레이션(Edge 음성 "현수", 쇼츠는 8% 빠르게), 하단 흰 자막과 노랑 강조 단어, 위쪽 큰 팝업 자막, 숫자·기사 카드가 빠르게 받쳐줍니다.
**한 화면이 3초 넘게 그대로 있지 않게** 하는 것이 핵심입니다.

## 2. 영상 구조 템플릿 (롱폼 8~12분)

| 구간 | 시간 | 목적 | 화면 | 소리 |
|---|---|---|---|---|
| ① 훅 | 0~3초 | 질문이나 충격적인 숫자로 시선 잡기 | 캐릭터 `shock` + 큰자막 질문 + 소품 팝 | 첫 프레임부터 바로 내레이션(무음 금지), pop |
| ② 판 키우기 | 3~15초 | "생각보다 심각하다": 숫자, 비교, 기사로 근거 대기 | number → compare → headline 카드 | 카운트 tick → boom, 기사에 형광펜 swish |
| ③ 약속 | 15~25초 | 오늘 무엇을 알려줄지 말하기(제목 카드) | title 카드(검은 띠 + "오늘의 주제" 칩) | tada, BGM 정식 진입 |
| ④ 본론 챕터 ×3~5 | 챕터당 1.5~2.5분 | 질문 → 설명 → 자료 → 한 줄 정리 | stage/list/compare/headline 번갈아 | 장면 전환마다 whoosh |
| ⑤ 반전/핵심 | 끝나기 2분 전 | "그런데 진짜 이유는…" | 캐릭터 `think` → `bulb` 소품 | ding |
| ⑥ 요약 | 30~45초 | 챕터 3줄 요약 | list 카드 | 항목마다 pop |
| ⑦ 아웃트로 | 마지막 10~20초 | 구독 유도 후 최종화면 자리 | outro(구독 버튼 클릭 모션) 후 8초는 비워 둠 | click + ding, BGM 페이드아웃 |

**쇼츠/20초 컨셉판**은 ①→②→③만 씁니다(파일럿이 이 구조입니다).

## 3. 컷 규칙
- **자막 덩어리 1개 = 컷 1개.** 덩어리가 바뀔 때마다 카메라가 1.00배와 1.10배를 번갈아 오갑니다(하드컷 펀치인). 같은 그림도 계속 움직여 보입니다.
- 한 컷 안에서는 2.5%만큼 천천히 밀고 들어갑니다(drift). 그래서 정지 화면처럼 보이지 않습니다.
- 컷 길이는 목표 **2.6초**, 최소 1.2초, 최대 4.5초입니다. ⟨실측: cut_target/min/max⟩
- 1.2초보다 짧은 덩어리에서는 줌을 바꾸지 않습니다. 너무 빨리 깜빡이지 않게 하기 위해서입니다.
- 장면 전환은 새 장면이 1.16배에서 1.0배로 0.22초 동안 줌아웃되며 들어오고, 전환 0.12초 전에 whoosh를 깝니다.
- 문장 사이 무음은 0.22초, 장면 사이는 0.32초, 같은 문장 안 덩어리 사이는 0.06초입니다. 숨 쉴 틈만 남깁니다.

## 4. 자막 규칙
### 4-1 하단 자막(내레이션 받아쓰기)
| 항목 | 값 |
|---|---|
| 글꼴 | Pretendard ExtraBold |
| 크기 | 66px (1080p 기준) ⟨실측: size⟩ |
| 색 | 흰색 #FFFFFF, 검정 외곽선 8px, 아래쪽 흐린 그림자 |
| 위치 | 가운데 정렬, 세로 88.5% 지점 ⟨실측: y⟩ |
| 길이 | 한 줄 최대 17자, 최대 2줄, 두 줄 길이가 비슷하도록 어절 단위로 나눔 |
| 표시 | 음성 시작 0.02초 전에 뜨고 다음 덩어리 직전까지 유지(깜빡임 없음) |

### 4-2 강조 단어
- 대본에서 `[[단어]]`로 감싼 단어는 **노랑 #FFE14D**로 표시합니다. ⟨실측: emphasis_color⟩
- 강조 대상은 숫자, 비교 결과("두 배"), 핵심 동사("파헤쳐")입니다. **덩어리당 1개, 많아도 2개까지만** 씁니다.

### 4-3 큰 팝업 자막 (`big:`)
- 글꼴은 Black Han Sans 128px, 흰 글씨에 빨강 #FF4D4D 둥근 박스, -2° 기울임입니다.
- 위치는 화면 위쪽 17%입니다. 하단 자막과 겹치지 않습니다.
- 0.22초 동안 125%까지 커졌다가 100%로 돌아오는 팝 애니메이션이고, pop 효과음과 같은 프레임에 뜹니다.
- 장면당 1개만 씁니다. 훅 질문, 충격 숫자, 챕터 제목에만 씁니다.

### 4-4 출처 표기 (`source:`)
- 자료(숫자, 기사, 이미지)가 나오는 장면은 **반드시** 오른쪽 위에 `출처: 매체 날짜 (도메인)`을 26px 반투명 박스로 작게 적습니다.
- 출처가 없으면 사전검사에서 경고가 뜹니다.

## 5. 효과음·배경음 타이밍 (모두 자체 합성이라 저작권 문제 없음)
| 순간 | 효과음 | 음량 |
|---|---|---|
| 장면 전환 0.12초 전 | whoosh | -3 dB |
| 큰자막이 뜨는 프레임 | pop | 0 dB |
| 소품 등장 | pop | -10 dB |
| 숫자 카운트업 중 | tick ×8 (점점 빨라짐) | -10 dB |
| 숫자 확정 | boom(충격) / ding(긍정) | -2 dB |
| 기사 형광펜 | swish | -4 dB |
| 막대·리스트 항목 등장 | pop | -6 dB |
| 제목 카드 | tada | -6 dB |
| 구독 버튼 | click + ding | 0 / -6 dB |

- **배경음(BGM)**: 104 BPM의 밝은 플럭 루프입니다(밝은 주제 `bright`, 경고·문제 주제 `tense`). 내레이션보다 -24 dB이고, 말할 때 사이드체인으로 더 내려갑니다(비율 6). ⟨실측: bgm_db⟩
- 최종 음량은 **-14 LUFS**(유튜브 기준), 트루피크 -1.5 dB입니다. ⟨실측: loudness⟩

## 6. 캐릭터·모션 규칙
- 생김새: 흰 원형 머리(반지름 78px), 검정 외곽선 7px, 점 눈, 콩 모양 컬러 몸통(파랑, 주황, 초록, 보라), 막대 팔다리, 둥근 손발, 바닥 그림자.
- **항상 움직입니다.** 숨쉬기 바운스, 3.1초마다 눈 깜빡임, 말할 때 입이 음성 크기에 맞춰 열리고 손짓을 합니다.
- 포즈 사전:
  - `talk` 설명
  - `point` 자료 가리키기
  - `shock` 충격: 눈이 커지고 떨림
  - `think` 의문: 턱을 괴고 눈썹 하나를 올림
  - `happy` 긍정: 깡총, 볼터치
  - `wave` 인사
  - `shrug` 모르겠음
  - `sad` 문제
  - `walk` 이동
- 포즈는 덩어리마다 바꿀 수 있습니다(`pose: [shock, think]`). 대사 감정과 포즈가 반드시 맞아야 합니다.
- 자료 카드 장면에서는 캐릭터가 왼쪽 아래 작은 진행자(78%)로 카드를 가리킵니다.
- 소품은 coffee, question, exclaim, sweat, bulb, money, arrow_up, arrow_down, sparkle, heart입니다. 등장할 때 팝하고 위아래로 둥실거립니다.

## 7. 자료화면 규칙
- 종류는 기사 제목 카드(`headline`), 숫자 카운트(`number`), 막대 비교(`compare`), 체크리스트(`list`), 이미지·스크린샷(`image`)입니다.
- **기사 카드**는 매체명을 텍스트로, 날짜, 제목 원문을 넣습니다. 실제 로고는 쓰지 않습니다. 카드는 아래에서 튀어 올라오고 -1.2° 기울어지며, 핵심 단어에 형광펜이 그어집니다.
- 자료는 **공개된 자료만** 씁니다(언론 기사 제목, 공식 통계·공식 사이트). 제목은 원문 그대로 옮기고, 수치는 기사 본문과 맞는지 확인합니다.
- 스크린샷을 쓸 때는 렌더링 전에 OCR로 개인정보를 검사하고, 발견되면 흐림 처리합니다.

## 8. 화면 확대 규칙
- 펀치인은 1.10배, 덩어리마다 번갈아 들어갑니다.
- 숫자가 확정되는 순간 숫자가 118%에서 100%로 튀는 강조를 넣습니다.
- 이미지 자료는 장면 내내 6% 켄번스 줌을 줍니다.
- 줌 중심은 장면의 `focus`(기본 화면 중앙에서 살짝 위)입니다.

## 9. 대본 작성 규칙 (PD 가이드)
- 한 문장은 **35자 이내**로 씁니다. 쉼표에서 자막 덩어리가 나뉘니까, 끊고 싶은 곳에 쉼표를 찍습니다.
- 질문하고 답하는 리듬으로 씁니다. "~일까요?" 다음에 숫자나 근거를 댑니다.
- 숫자는 아라비아 숫자로 씁니다. 자막에는 숫자로 나오고, 음성은 자동으로 한국어 읽기("405잔"→"사백오 잔")로 바뀝니다.
- 존댓말 "~입니다/~죠/~는데요"를 섞어 대화하듯 씁니다.
- 음성 검수에서 계속 틀리는 표현은 뜻이 같은 다른 말로 바꿉니다(예: "두 배가 넘죠"→"두 배가 넘는 수치죠").

## 11. 대본 파일(YAML) 문법 요약
```yaml
title: 영상 제목
voice: {backend: auto, speed: 1.05}      # auto=Edge 현수 음성 → 안 되면 오프라인
bgm_mood: bright                         # bright | tense
scenes:
  - type: stage | number | compare | headline | title | list | image | outro
    say: "문장 [[강조]]"  또는  ["문장1", "문장2"]
    big: "큰 팝업 자막"        # 선택
    source: "매체 날짜 (도메인)" # 자료 장면은 필수
    cast: [{pose: [shock, think], x: 0.5}]
    props: [{kind: coffee, x: 0.7, y: 0.5, at: 1}]
    # number:  value, unit, label, sub
    # compare: items: [{label, value, color, at}], unit, label
    # headline: outlet, date, title, highlight, highlight_at
    # title: kicker, title     list: items, label     image: path
```

## 12. 숫자로 지키는 규칙 (스마트대디 편집 스킬에서 배움, `style.yaml rules:`로 자동 점검)
"적게", "빠르게" 같은 말은 안 지켜지고 숫자는 지켜진다. 빌드할 때 아래를 자동으로 재서 위반이 있으면 보고서에 ⚠로 표시한다.

| 규칙 | 값 | 이유(스마트대디 실제 피드백) |
|---|---|---|
| 효과음 개수 | 롱폼 분당 6개 이하, 모션 쇼츠 분당 24개 이하 | 214개를 넣어 "누가 봐도 너무 많다", 15초에 12개로 "다닥다닥" |
| 효과음 사이 간격 | 0.35초 이상 (숫자 카운트 tick은 예외) | 같은 이유 |
| 휙(whoosh) | 챕터 전환과 3장면에 1번 | "휙은 잦으면 안 된다" |
| 소품 pop | `sfx: true` 로 명시한 것만 | "모션이 뜰 때마다 넣지 않는다" |
| 내레이션 속도 | 6.8~8.6음절/초 (기준 7.7) | 6.4는 "너무 느리다", 8.4는 "정신없다" |
| 자막 뜨는 시각 | 목소리 시작 +0.15초, 말 끝 +0.2초까지 | "목소리가 1.0초인데 자막이 0.8초에 뜬다" |
| 같은 구도 | 10초 초과 금지 | "PPT처럼 카드만 나열" |
| 숫자 장면 | 출처(source) 필수, 꾸민 숫자 금지 | "가짜 차트·가짜 댓글은 AI 느낌" |
| 첫 20초 | 영상이 답할 질문을 던진다 | "초반 30초에 시청자가 남을지 떠날지 갈린다" |
| 카드 끝 | 0.5초 정지 | 편집 때 늘려 쓰려고 |

### 모션그래픽 원칙
실제 자료가 주인공이고 모션은 짧은 강조만 한다 · 같은 효과를 되풀이하지 않는다('쾅+파티클'은 클라이맥스 1~2번) · 한 화면에 한 생각 · 여러 항목은 말하는 순서대로 한 칸씩 켠다(아직 안 나온 칸은 흐리게) · 숫자는 말하는 순간 0부터 굴린다 · 강조 낱말은 색 글자 대신 반전 스티커(흰 상자+검은 글자, 살짝 기울임).

### 피드백 루프

## 13. 쇼츠 공장 원칙 6가지 (2026-10-23, 현철님이 공유한 "공장이 지키는 원칙"에서 배움)
쇼츠는 `shorts/make_short.py` 가 아래를 자동으로 점검한다(`style.yaml shorts:`). 세로 1080×1920.

1. **소재는 오늘에서** — 오늘 뉴스와 72시간 안에 터진 영상에서 5개를 고른다. 뉴스 3, 오래 가는 원리형 2.
2. **40~50초, 줄마다 할 일** — 훅 · 반전 · 핵심 · 내 관점 · 오늘 할 것 · 끝. 설명만 두 줄 이어지지 않게.
3. **아래 18%는 비운다** — 유튜브 버튼이 덮는 자리. 렌더할 때마다 비었는지 검사한다(세로 1920px 중 y 1574 이후).
4. **자막은 목소리에 맞춰** — 받아쓰기로 단어마다 시간을 맞추고, 한 화면에 13자 안팎으로 나눈다.
5. **내 관점 한 줄은 꼭** — 없으면 다른 채널과 똑같은 영상이 된다. 첫 줄은 직접 손본다.
6. **출처에 없는 숫자는 안 쓴다** — 기사 원문을 열어 확인하고 설명란에 출처를 남긴다.

**우리가 한 구현·검증**: 자막 경계 19개를 음성 에너지와 독립 비교해 모두 실제 말 사이 골짜기 ±0.2초 안에 있고 평균 오차 0.10초였다. 아래 18% 검사는 정상 장면은 통과시키고 일부러 출처 표기를 1700px 에 놓은 장면은 잡아냈다. 규칙 점검은 정상 대본은 통과시키고 잘못 만든 대본 6종(역할 누락, core 연속, 근거 없는 숫자, 원문 미확인, 오래된 뉴스, 짧은 길이)을 모두 잡아냈다.

**이 원칙이 잡아낸 우리 실수**: 첫 파일럿의 기사 게재일을 주소 번호로 2023.12.22 라고 썼으나 원문은 2023.12.25 였다(06번을 이미 지켰다면 나지 않았을 오류).

## 14. 외부에서 만든 소재 (Pavo AI, Digen AI 등) 규칙 (2026-10-25)
1. 외부 영상·이미지는 장면 길이에 맞춰 카드 안에 넣는다. 소리는 버리고, 짧으면 반복 재생, 길면 앞부분만 쓴다. 쇼츠는 카드가 안전 영역(아래 18% 밖)에 들어간다.
2. AI 소재는 `tool, model, generated_on` 을 반드시 기록한다. 약관을 확인하지 않은 도구는 빌드가 경고한다(`style.yaml external_tools.terms_checked`).
3. 영상에는 'AI 생성 · 도구' 배지와 출처 표기가 자동으로 붙고, 설명란에 AI 생성 소재가 적힌다. 도구가 넣은 워터마크는 가리지 않는다.
4. 화면 속 글자는 AI 에게 맡기지 않고 우리가 얹는다. 실존 인물·유명 캐릭터·상표를 닮게 만들지 않는다.
5. 개인정보·미공개 자료·실존 인물 사진은 외부 사이트에 올리지 않는다.
6. 사이트에서의 생성·결제는 현철님이 하고, 저는 프롬프트(소재 요청서)와 편집·검수를 맡는다. 자세한 내용은 `docs/외부도구.md`.
