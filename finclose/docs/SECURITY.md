# 보안 및 금융정보 보호 (SECURITY)

## 현재 보안 수준 — 운영 사용 비권장
**MVP는 단일 PC 로컬 사용을 전제로 한다.** 사용자/역할 전환은 화면에서 선택하는 데모 기능이며
**인증이 아니다.** 운영환경 투입 전 사내 SSO/AD 연동, HTTPS, 접근통제가 반드시 필요하다.

## 구현된 통제
- 기본 바인딩 `127.0.0.1` (외부 접근 차단). `FINCLOSE_HOST`로 변경 시 경고 출력.
- 외부 네트워크 전송 없음: 외부 AI·클라우드 API 호출 코드가 없다. PWA 서비스워커는 API 응답을 캐시하지 않는다.
- 업로드: 확장자 화이트리스트(xlsx, xlsm, csv, pdf, txt), 매직바이트 검사, 크기 제한(기본 50MB, `FINCLOSE_MAX_UPLOAD_MB`),
  디스크 여유공간 확인, 저장명은 UUID(사용자 파일명은 표시용으로 정화만), 경로 조작 불가.
- 원본 파일 읽기전용 권한(0o444), SHA-256 기록, 처리 중 수정 없음.
- Excel 매크로(xlsm)는 실행하지 않고 값만 읽는다. ZIP 폭탄 방지: 압축해제 크기 상한 검사.
- 감사 로그 해시 체인(이전 레코드 해시 포함) — `/api/audit/verify`로 변조 탐지.
- 감사 로그에 비밀번호·API 키를 기록하지 않는다(애초에 저장하지 않음). 행 단위 금액 데이터는 감사로그가 아닌 실행 결과 파일에 보관.
- 직무분리: 실행 생성자 ≠ 승인자.
- 비밀정보는 `.env`(git 제외)로만 주입. 현재 필수 비밀정보 없음.

## 데스크톱 앱
- 서버는 항상 127.0.0.1에만 열림(다른 PC에서 접속 불가). 창을 닫으면 서버 종료.
- 종료·폴더 열기 API는 데스크톱 모드에서만 존재하고 사용자 지정 헤더를 요구 → 다른 웹사이트가 브라우저를 통해 호출할 수 없음(CORS 사전요청 차단). 폴더 열기는 정해진 3개 폴더만.
- 연습 모드는 별도 폴더(practice-data)를 써서 가상 이력이 업무 감사기록에 섞이지 않음.
- 실행 파일은 코드 서명되지 않음 → 운영 배포 전 사내 코드서명 인증서로 서명 권장.

## 보존·백업 정책(권고)
- `data/` 디렉터리를 일 1회 사내 백업 저장소로 복사(암호화 볼륨 권장). 보존기간은 회사 기록보존 규정을 따른다.
- 임시 실행 디렉터리(`*.tmp`)는 서버 시작 시 정리, 비정상 종료된 RUNNING 실행은 FAILED로 표시.
- 삭제 API는 제공하지 않는다(운영 데이터 삭제는 관리자가 백업 후 수동 수행).

## 미구현(운영 전 필수)
SSO/다중 사용자 인증, 저장 데이터 암호화, 백신 연동 검사, 세분화된 데이터 접근권한, HTTPS 종단.
