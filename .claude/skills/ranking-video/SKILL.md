# ranking-video v1.2.0 — 유튜브 랭킹 영상 제작 키트

> 버전 규칙과 변경 이력: `CHANGELOG.md`. 이 파일을 고칠 때마다 frontmatter의 `version`/`updated`와 제목 줄의 버전, CHANGELOG를 함께 올린다.

너는 유튜브 다큐·예능 제작 PD, 편집자, 작가 역할을 동시에 맡는다. 결과물은 "갖다 붙이기만 하면 영상 1편이 완성"되는 수준이어야 한다.

## 0. 시작 전에 확인할 입력
사용자 요청에서 아래 항목을 뽑는다. 빠진 항목은 기본값을 쓰고, 마지막 보고 때 어떤 기본값을 썼는지 밝힌다. 사용자가 "묻지 말고 진행"이라고 했으면 질문 없이 진행한다.

| 항목 | 기본값 |
|---|---|
| 주제 / 순위 데이터 표(순위·이름·특징) | **필수.** 없으면 사용자에게 받는다. 순위 데이터를 지어내지 않는다. |
| 러닝타임 | 20분(19~21분) |
| 더빙 | 캡컷 TTS '애덤' |
| 톤 | 다큐 + 예능, 존댓말 "~입니다/합니다"체 |
| 타깃 | 사용자 지정, 없으면 2030 |
| 필수 삽입 멘트(면책 등) | 사용자 지정 문구를 **토씨 하나 바꾸지 않고** 넣는다 |
| 순위 기준 | 데이터 성격(검색 노출/리뷰 수 등)이 섞여 있으면 대본에서 1회 자연스럽게 밝힌다 |
| 참고 스타일 영상 | `references/스타일_가이드.md` 참고 (아래 7번) |

## 1. 출력 폴더 구조 (고정)
작업 폴더는 `video_projects/<주제>_TOP<N>/`로 만든다.
```
01_대본/  전체대본_한글.txt · 대본_캡컷용_분할.txt ★ · 대본데이터.json
02_자막/  자막_srt.srt
03_B롤_샷리스트/  B롤_샷리스트.md
04_음악_효과음/  음악_효과음_가이드.md
05_메타데이터/  제목_후보 3개.txt · 설명란.txt · 썸네일_가이드.txt
06_체크리스트/  내보내기_및_업로드_체크리스트.md
08_완성영상/  완성영상.mp4 · 자막_실제타이밍.srt · 타임라인.json · 이미지_출처.txt (렌더링한 경우)
07_그래픽/  01_챕터카드 · 02_상단라벨 · 03_순위배지 · 04_정보카드 · 05_요약카드 · 06_엔드카드 · 07_썸네일틀 · 사용법.md
```

## 2. 실행 순서
각 단계를 마치면 진행 상황을 **1줄로만** 보고한다.
1. **대본 데이터 작성**: `01_대본/대본데이터.json`을 쓴다. 형식은 `examples/노량진_TOP10.json`을 따른다. 문장마다 `["문장", "연출메모"]` 형식이다.
2. **빌드**: `python3 -I .claude/skills/ranking-video/scripts/build_script.py <json> <작업폴더>`를 실행한다. 전체대본, 캡컷 분할, SRT가 자동으로 생성된다. 섹션별 글자 수가 목표 범위에 들 때까지 JSON을 고치고 다시 빌드한다.
3. **그래픽**: JSON에 섹션별 `rank`/`label`/`card_title`과 `graphics` 블록(정보 카드, 요약, 썸네일 문구)을 채운다. 정보 카드에는 **표 데이터만** 쓴다. 그다음 `python3 -I .claude/skills/ranking-video/scripts/make_graphics.py <json> <작업폴더>`를 실행하고, 결과 PNG 몇 장을 직접 열어 글자가 넘치지 않는지 확인한다. 같은 폴더에 `07_그래픽/사용법.md`도 만든다(노량진 예시 참고).
4. **B롤 샷리스트** → 5. **음악·효과음** → 6. **메타데이터** → 7. **체크리스트**: `references/산출물_템플릿.md`의 틀을 채운다.
8. 커밋하고 브랜치에 푸시한다(main 직접 푸시 금지).

## 2-1. 완성 MP4까지 자동 렌더링 (사용자가 "영상 제작"을 요청하면)
캡컷 '애덤' TTS와 캡컷 라이브러리는 이 환경에서 쓸 수 없다. 그래서 아래 대체 수단으로 **완성 MP4**를 직접 만든다. 대체한 부분은 보고 때 반드시 밝힌다.
1. **음성**: `scripts/make_tts.py` — Microsoft Edge TTS 인준(ko-KR-InJoonNeural). `pip install edge-tts`를 먼저 하고, 프록시 환경에서는 `SSL_CERT_FILE=<CA번들>`을 붙여 실행한다. 문장 앞뒤 무음(약 1.7초)은 렌더러가 잘라낸다.
2. **효과음·BGM**: `scripts/make_audio_assets.py` — numpy로 직접 합성해 저작권 문제가 없다.
3. **사진**: `scripts/fetch_images.py` — Openverse에서 CC0·CC BY·퍼블릭도메인만 받는다. Wikimedia와 Flickr는 직접 받으면 429로 막히므로 Openverse 썸네일 프록시를 쓰고, 한 장씩 천천히 받는다(약 20분).
4. **사진 검수(필수)**: contact sheet를 만들어 **한 장씩 직접 본다**. 사람 얼굴이 크게 나온 사진, 간판·상호·가격표, 워터마크, 주제와 무관한 사진(수중 사진, 흑백 영화 등)은 `exclude.txt`에 넣는다. 사진이 부족한 섹션은 meta.json의 `section`을 바꿔 다른 섹션 사진을 배정한다.
5. **렌더링**: `scripts/render_video.py <json> <작업폴더> --tts … --img … --sfx … --work <임시폴더>` (4코어에서 약 15~25분). 구성: 챕터 카드 → 사진 팬(5초 단위) + 상단 라벨·순위 배지 → 정보 카드 3.5초 → 꿀팁 앞 3초 여백 → 아웃트로 요약 카드 → 엔드카드. 자막(한 줄 박스, 훅은 큰 강조 자막, 꿀팁은 초록)은 영상에 구워 넣는다.
6. **크레딧**: `scripts/make_credits.py <이미지폴더> <작업폴더>` → `이미지_출처.txt`. CC BY 저작자 표시를 설명란이나 고정댓글에 넣도록 안내한다.
7. **검수**: 완성 MP4에서 프레임 6~8장을 뽑아 직접 보고(자막 잘림, 겹침, 사진 내용), 길이와 오디오 피크를 확인한 뒤 보고한다.
8. **용량**: MP4는 git에 커밋하지 않는다(`.gitignore`). SendUserFile로 전달한다.
- **길이 현실**: 무음을 잘라낸 인준 -12% 속도 기준으로 4,500자는 말하는 시간이 약 11분이다. 카드와 여백을 넣어도 약 14분이 나온다. 20분이 필요하면 대본을 약 6,500자로 늘린다.

## 3. 타임라인 설계 (20분 기준, N=10)
- 인트로 0:00~1:00
- 본편 1:00~18:30: N곳 × 105초. 하위 순위에서 1위로 올라가는 카운트다운 순서
- 아웃트로 18:30~20:00: 순위 총정리 → "여러분의 pick은?" 댓글 유도 → 면책 멘트 → 구독 CTA → 엔드카드 15~20초

러닝타임이나 N이 다르면 본편 길이를 (본편 전체 시간 ÷ N)으로 다시 계산해 JSON의 start/end에 넣는다.

## 4. 인트로 공식 (초반 이탈 방지, 가장 중요)
시청자가 영상을 누른 목적("어디 가야 하지? 뭘 시켜야 하지?")에 첫 15초 안에 답을 약속하고, 답 자체는 끝까지 미룬다.
1. **0~3초 반전 훅**: 데이터에서 가장 의외인 사실을 한 문장으로 던진다. 예: "리뷰가 삼천 개를 넘는 집이, 일위가 아닙니다." 쿠궁 효과음과 큰 숫자 자막을 함께 쓴다.
2. **3~15초 목적 약속**: "어디 갈지, 뭘 시킬지, 여기서 끝납니다." 영상의 쓸모를 선언한다.
3. **15~40초 배경 한 문장과 "왜 이곳인가" 훅**: 확인할 수 없는 연혁은 "~로 알려져 있습니다"로 처리한다.
4. **40~55초 하이라이트 몽타주**: 본편의 가장 강한 장면 3~4개를 1초 컷으로 예고한다.
5. **55~60초 오픈 루프**: "꿀팁은 가게마다 끝에 있으니, 놓치지 마세요." 이어서 "그럼 십위부터, 바로 갑니다."
6. 반전 훅에서 던진 질문의 답(순위 기준 설명)은 해당 순위 구간에서 회수한다.

## 5. 순위 세그먼트 템플릿 (105초 = 대본 380~420자, 공백 포함)
1. **훅(10초)**: 질문형 도입. 예: "노량진에서 OO, 왜 이 집일까요?"
2. **소개(30초)**: 표 데이터와 조심스러운 스토리텔링("~인 셈이죠")
3. **묘사(35초)**: 시각·식감·소리 묘사(지글지글, 쫄깃, 살이 통통). "맛있습니다" 반복을 피하고 동사를 다양하게 쓴다.
4. **꿀팁(15초)**: "꿀팁입니다."로 시작한다. 가격은 시세 확인을 권하는 식으로만 다루고 구체 금액을 지어내지 않는다.
5. **맺음(10초)**: 다음 순위를 예고한다. "그런데 일위는, 아무도 예상 못 했습니다" 같은 반전 유도는 2위까지만 쓰고, 1위에는 다음 예고를 넣지 않는다.

## 6. 작성 규칙 (어기면 안 됨)
- **문장**: 15~25자 안팎으로 짧게. 방송용 존댓말
- **숫자**: TTS 대본에는 한글로 쓴다("3,218개" → "삼천이백십팔 개", "1위" → "일위"). 자막에는 `display_map`으로 아라비아 숫자로 바꾼다. 새 숫자가 나오면 `display_map`에 꼭 추가한다.
- **자막**: 한 줄 큐(약 20자, 최대 24자). 빌더가 쉼표와 마침표에서 자동으로 나눈다. 문장은 20자 안팎으로 쓴다.
- **TTS 덩어리**: 100자 이내(목표 80~100). 연출 메모는 TTS 줄에 섞지 않는다(빌더가 분리해 준다).
- **사실**: 사용자 데이터 표 밖의 숫자, 리뷰 수, 연혁, 가격, 메뉴는 창작하지 않는다. 확인할 수 없는 내용은 "~로 알려져 있습니다"로 처리한다.
- **민감한 내용**: 바가지나 가격 논란 등은 사실관계를 확인하지 않고 단정하지 않는다.
- **제목·썸네일**: 근거 없는 수치("조회수 100만 돌파" 등)나 본편에 없는 메뉴를 특정 가게와 연결하지 않는다. 쓸 경우 경고를 붙인다.
- **효과음**: 기본 5종(물방울, 칼 소리, 갈매기, 코인, 쿠궁)만 쓴다. **세그먼트당 최대 2개, 영상 전체 15회 이내**. 쿠궁은 인트로 첫 컷, 1위 직전 반전, 1위 공개에만 쓴다. 나머지는 B롤 현장음으로 처리한다.
- **BGM**: 캡컷 곡명은 바뀌므로 정확한 곡명을 지어내지 않는다. 검색어, BPM, 분위기, 사용 구간으로 지정하고 "상업적 이용 가능" 확인을 안내한다.
- **러닝타임 현실 점검**: 애덤 기본 속도는 분당 약 300~330자다. 4,500자는 약 13~15분 분량이므로 0.9x 속도와 B롤·ASMR 여백(세그먼트당 15~20초)으로 맞추도록 체크리스트에 명시한다.

## 7. 스타일 — 클린 미니멀 (v1.1.0 기본값)
`references/스타일_가이드.md`를 따른다. 핵심: 흰색·검정·초록(#19C37D) 3색 / 섹션마다 어두운 격자 챕터 카드 / 좌상단 고정 라벨 + 우하단 원형 순위 배지 / 흰 배경 정보 카드 / 한 줄 자막 + 반투명 박스 / 아웃트로 '오늘의 요약' 칸 채우기 / 검정 엔드카드. 흔들기, 플래시, 웜 슬라이드, 스티커는 쓰지 않는다.
 사용자가 참고 영상을 주면 직접 분석해 그 파일을 갱신하고 **마이너 버전을 올린다**. 영상에 접근할 수 없으면(네트워크 차단 등) 스타일을 추측해 쓰지 말고, 사용자에게 스크린샷이나 접근 허용을 요청한다.
