# 스크린샷 → 경제 영상 1세트

결과물은 항상 **영상(mp4) + 제목 + 설명란(요약+해시태그) + 썸네일**이 한 세트다. 엔진은 `video-studio/`, 제작 규칙은 `video-studio/STYLE_GUIDE.md`(벤치마킹 3편 분석)를 따른다.

## 0. 버전 확인 (작업 시작 전 매번)
`python video-studio/make_video.py --version` 결과가 이 스킬의 `version`(위 머리말)과 같은지 확인한다.
다르면 진행하지 말고 현철님께 "스킬 vX, 엔진 vY로 버전이 다릅니다"라고 알린 뒤 `git pull`로 맞춘다.
버전을 올릴 때는 `video-studio/VERSION`, 이 파일의 `version`, `CHANGELOG.md`를 함께 바꾸고 git 태그 `econ-video-v<버전>`을 붙인다.

## 절차 (순서를 바꾸지 않는다)

1. **형식 질문** — 스크린샷을 받으면 먼저 한 줄로 묻는다: "롱폼으로 만들까요, 쇼츠로 만들까요?" (AskUserQuestion: 쇼츠(45~60초) / 롱폼(8~15분))
2. **주제 조사** — 스크린샷의 핵심(종목·지표·정책·기사 제목·숫자)을 읽고 WebSearch로 최대한 가까운 원문을 찾는다. 우선순위: 공식 기관(한국은행·통계청·금감원·금융위·국토부·한국거래소·DART) → 한경·연합뉴스·네이버 랭킹뉴스 → 나무위키(배경 설명용, 수치 근거로는 쓰지 않음). 수치는 출처 URL·기준일을 기록하고, 확인하지 못한 숫자는 쓰지 않는다.
3. **영상 설계 요약 + 예시 3개 질문** — 조사 결과로 흐름·핵심 포인트를 짧게 정리한 뒤, 주제에 맞는 **방향 예시 3개를 단답식으로** 묻는다 (AskUserQuestion 1개 질문, 보기 3개). 예: "① 내 대출이자 관점 ② 집값 영향 관점 ③ 부부 대화형(남·여)". 각 보기는 한 줄.
4. 현철님이 하나를 고른다.
5. **제작** — `video-studio/projects/<날짜-주제>/project.json`을 작성하고 `python make_video.py projects/<...>/project.json` 실행.
   - 목소리: 기본 **여의도남자**. 대화가 필요하면 시청자 질문 역할로 **여의도여자**(scene에 `"voice":"여의도여자"`, 필요하면 `"instruct"`).
   - 쇼츠: 반말, speed 1.1, 상단 고정 제목 2줄(`header`), 머니치트키 공식(훅 3초 → 재정의 → 개념 이름 → 숫자 대비 → 반전 → 내 생활 → 양자택일/체크리스트 + 팔로우). **40~50초, 줄마다 역할 하나(훅·반전·핵심·내 관점·오늘 할 것·끝), 설명만 두 줄 이어 붙이지 않는다. 아래 18%는 비운다(날짜·핸들은 위쪽 한 줄), 자막은 한 화면 14자 안팎**
   - 롱폼: 존댓말, speed 1.0, 한 문장=한 장면, 경제학똑똑 공식(양자택일 훅 → 역설 수치 → 비유 → 쪼개기 → 시나리오 3개 → 오해 깨기 → 숫자 예시 → 체크리스트 → 세금·제도 → 3줄 요약 + 첫 질문 회수).
   - 장면 visual 타입: mascot / dialogue / title / bignumber / bars / line / compare / checklist / flow / icons (형식은 `video-studio/README.md`).
6~8. **업로드 세트** — `output/`의 `video.mp4`, `thumbnail.png`(쇼츠는 `thumbnail_shorts.png`도), `title.txt`, `description.txt`, `tags.txt`, `subtitles.srt`, `업로드정보.md`를 SendUserFile로 보내고, 제목·설명란은 채팅에도 붙여 넣기 좋게 보여 준다.

## 벤치마킹 모드 ("○○ 같은 채널 N개 찾아서 공통 인기 주제로 만들어 줘")
1. 기준 채널과 같은 장르·형식(얼굴 없는 그림+내레이션)의 채널을 YouTube 검색으로 찾는다 (채널 검색 + 주제 키워드 영상 검색으로 채널 모으기).
2. `python video-studio/tools/channel_videos.py <채널ID...>` → 각 채널 인기순 상위 30개 제목·조회수 수집.
3. 주제 키워드로 묶어 '다룬 채널 수 → 합계 조회 → 최고 조회' 순으로 공통 인기 주제를 고른다. 표를 `projects/<...>/research.md`에 저장.
4. 해당 주제 최고 조회 영상 2개의 설명란·챕터(`youtubei/v1/next`)로 공통 구조를 뽑는다. 이 구조를 80% 유지하고, 원본이 약하게 다룬 각도 하나를 포커스로 바꾼다 (20%). 대본·비유·캐릭터는 독립 작성.
5. 원본이 롱폼이면 롱폼으로 만든다. 수치는 검증해 설명란 '계산 가정과 자료'에 적고, 확정되지 않은 제도(예: 개편 중인 한도)는 숫자 대신 '확인 필요'로 말한다.
6. 장면에 `"chapter"`를 달면 설명란 타임라인이 자동 생성된다 (3개 이상, 첫 항목 00:00).

## 목소리 실행 조건 (모바일로 스샷만 보내도 목소리 포함 완성본)
- 목소리는 항상 yeouido-voice 규격: 여의도남자(기준음성 복제) / 여의도여자(Sohee 프리셋). 다른 TTS로 대체 금지.
- 엔진 두 경로 (같은 Qwen3-TTS 엔진·같은 기준음성): `--voice auto`가 알아서 고른다.
  - **cloud**: 클라우드 세션에서 직접 구동. 새 세션 첫 제작이면 **먼저 `bash video-studio/setup_cloud.sh`를 백그라운드로 시작**(10~15분)하고, 그동안 조사·대본·화면을 만든다.
  - **voicebox**: 현철님 PC의 Voicebox가 켜져 있으면 그쪽을 쓴다.
- 읽는 글만 `voice/pronounce.py`로 자동 교정(숫자·소수·%p·개월·ETF/COFIX 등 약어). 자막은 원문 그대로.
- **원화 금액은 숫자와 '원'을 붙여 한 덩어리로 읽는다 (현철님 규칙)**: '100만 원' → [백만원], '1억 8천만 원' → [일억팔천만원], '1,382만 원' → [천삼백팔십이만원]. 띄어 읽으면 '백만 / 원'처럼 끊긴다. 자막 표기는 맞춤법대로 '100만 원' 유지. (`won_glue`, 천 단위 쉼표도 자동 처리)
- **소수점은 '점'이 아니라 '쩜'으로 읽는다 (현철님 규칙, 2026-10-14)**: '3.3%' → [삼쩜삼 퍼센트], '16.5%' → [십육쩜오 퍼센트], '1.5배' → [일쩜오배]. 퍼센트뿐 아니라 모든 소수에 적용. 자막 표기는 '3.3%' 그대로. (`pronounce.py` 소수 규칙)
- **더빙 품질 (v1.10.0 — 현철님 요청, 자동 적용)**: TTS 자연스러움 가이드(ElevenLabs·Typecast 등) 반영
  - 장면 대사를 **문장 단위로 따로 생성**해 문장부호에 맞는 쉼으로 잇는다 (마침표 0.26초·물음표 0.34초·느낌표 0.30초). 긴 덩어리를 한 번에 읽히면 억양이 흐트러지고 오독이 늘어남
  - 문장마다 **받아쓰기로 자동 검수**: 대본 숫자가 받아쓰기에 없거나 글자 오류율이 8%를 넘으면 시드를 바꿔 최대 3번 생성하고 가장 정확한 테이크를 고른다 (연음 규칙 적용 — '연준은'→[연주는]은 정상)
  - 그래도 남는 오독은 지금처럼 qa_video로 확인해 문장을 고쳐 쓴다. 자주 틀리는 말: 닻·잔고(→기준점·규모), 하한가(→가격 제한 폭), 계좌(문맥 따라 '쪽')
- 말 속도: 쇼츠 1.05배(빠르면 기계음처럼 들림), 롱폼은 여의도남자만 1.08배. 최종 음량 -14 LUFS.
- **백그라운드 작업은 2시간 제한**: 영상 한 편 = 한 작업으로 나눠 실행한다(롱폼 2편 이상을 한 작업에 넣지 않기). 음성은 문장마다 저장되므로 끊겨도 다시 실행하면 이어서 만든다. 다른 작업의 '완료 신호'를 기다리는 대기 작업을 만들지 않는다.
- 엔진 준비 전에는 `--preview-silent`로 화면을 먼저 보여 줄 수 있지만, 업로드용은 반드시 목소리 버전.

## 자막·목소리 싱크 (AI 티 안 나게, v1.4.0 — 자동 적용)
- 장면 음성: 앞뒤 무음 정리 → 방송 톤 후처리(저역 컷·따뜻함·또렷함·치찰음 완화·부드러운 압축) → 속도. 장면 사이 쉼: 롱폼 0.30초 / 쇼츠 0.14초 (`pause`로 조절).
- 자막 시작 = **파형에서 찾은 '쉼 뒤 말 시작' 순간 − 0.06초** (Whisper 단어 시각은 대략 위치 찾기에만 사용 — Whisper는 쉼 안쪽으로 0.3~0.6초 일찍 찍힘).
- 장면 클립은 영상만 만들고, 음성은 정확히 프레임 길이로 맞춘 PCM을 하나로 이어 **마지막에 한 번만** 인코딩 (장면마다 AAC 인코딩하면 장면당 ~35ms씩 누적 지연).
- BGM: 코드로 합성한 로파이(롱폼)/펄스(쇼츠), 목소리 나올 때 35%로 자동 더킹, 최종 -14 LUFS. 끄려면 `"bgm": "none"`.
- `caption`(자막을 대사와 다르게)은 **대사와 문장 수·순서를 똑같이** 쓴다 (문장 대 문장으로 맞춰 싱크).
- 검수: `python3 video-studio/voice/sync_check.py projects/<...>` → '통과'(평균 오차 ≤0.12초, 0.25초 초과 0개)여야 보낸다.

## 목소리 검수 (업로드 세트 보내기 전 매번)
- `~/.cache/yeouido-tts/venv/bin/python video-studio/voice/qa_video.py projects/<...>/project.json` 로 받아쓰기 → 대본과 비교.
- 뭉개진 단어는 `voice/lexicon.json`에 자연스러운 대체어를 추가하고(사유 기록), 그 장면의 `audio/<id>_*.wav`만 지워 다시 만든다.
- 표준 발음대로 적힌 것은 정상(예: 금리인하 → [금리이나]). '같은 음절 반복·단어가 둘로 쪼개짐·숫자 오독'만 고친다.

## 저작권·캐릭터 원칙 (v1.3.0)
- 마스코트는 오리지널 **'여의도 개미'**: 캐러멜색 얼굴 + 더듬이, **비즈니스 캐주얼**(남: 하늘색 셔츠+카멜 가디건 / 여: 흰 블라우스+코랄 가디건+더듬이 리본). 정장·넥타이·흰 둥근 얼굴 금지 (벤치마킹 채널 캐릭터와 닮지 않게).
- 썸네일 기본: `layout: split`(왼쪽 캐릭터 + 오른쪽 큰 숫자 패널 `big`) + `background: office`(창밖 도시·책상·노트북). 타 채널 썸네일 구도(가운데 캐릭터+좌우 아이콘+화살표) 그대로 따라 하지 않기.
- 손 모양은 오해 소지가 없는 것만 (손가락 하나 세우기 금지 → 만세·가리키기·으쓱).
- 폰트 OFL(Pretendard·Black Han Sans), 아이콘·배경은 코드로 직접 그림, 목소리 Qwen3-TTS(Apache-2.0), 데이터는 출처 명시.

## 채널·썸네일 규칙 (v1.6.0 — 현철님 지정, 매번 적용)
- 채널: **월급쟁이 재테크 스킬(월재스)** · @moneyskill26. 영상 워터마크·project.json `channel`에 이 이름/핸들을 쓴다.
- 채널 배너색은 **남색 + 금빛**이지만, 썸네일 배경을 매번 남색으로 하지 않는다 (아래 '분위기 50% 이상 다르게' 규칙이 우선).
- **썸네일 분위기는 회차마다 직전 회차들(최소 최근 4편)과 50% 이상 다르게 (v1.8.0 — 현철님 규칙, 매 회차 적용)**
  - 이유: 유튜브 스튜디오 목록에서 썸네일이 다 비슷해 '양산형'처럼 보임
  - 다섯 축 중 **3개 이상**을 직전 회차들과 다르게: ① 레이아웃(컨셉) ② 배경색 ③ 문구 위치·모양 ④ 캐릭터 크기·위치(없음 포함) ⑤ 강조 요소(숫자판·그래프·영수증·비교칸·휴대폰 등)
  - 컨셉(`thumbnail.layout`): `warning`(노랑 경고판·사선 띠·빨간 삼각형) / `scale`(민트 배경 저울·두 접시 비교) / `versus`(밝은 비교칸·상단 형광펜·캐릭터 없음) / `chart`(크림 모눈종이+꺾은선·포스트잇, `dark: true`면 검정판+네온 선) / `bignum`(초록·주황·보라 단색+초대형 숫자·빼꼼 캐릭터) / `receipt`(진한 단색+영수증·도장·오른쪽 문구) / `board`(증권 전광판) / `archive`(흑백 옛날 사진 + 검정 배경 빨간 초대형 글씨 + 노랑 띠 반전 문구 — 역사·과거 데이터 회차용, `big`·`line1`·`line2`·`photo_caption`, v1.12.0) / `split`(사무실) / `phone`(햇살+휴대폰)
  - **최근 4편에 쓴 컨셉은 다시 쓰지 않는다** (make_video가 겹치면 ⚠ 경고). 배경색 테마도 직전 회차와 겹치지 않게
  - 새 컨셉이 필요하면 `studio/concepts.py`에 추가해 목록을 늘린다
- **썸네일은 매 회차 4종(A~D)을 만든다 (v1.9.0 — 현철님 규칙)**: `thumbnail.variants`에 서로 다른 컨셉·배경색·폰트 4개를 넣는다 (A는 `{}`=기본 thumbnail). 다운로드 묶음에 `…_썸네일A~D.png`로 들어가고, 현철님이 하나를 골라 올린다. 4종끼리도 다섯 축 중 3개 이상 다르게
- **썸네일 폰트 = 요즘 대표 썸네일 폰트를 영상마다 다르게 돌려 쓴다** (같은 폰트 반복 = 양산형 느낌)

   - 그 변수를 **경제학적 논리**로 풀 수 있으면 풀고, 못 풀면 **기술적으로 대처하는 행동요령**을 주제로 삼는다
   - 투자 권유 아님 문구, 출처·기준일 표시
3. **근거 수집 기준 (현철님 정정 2026-10-23)**: 출퇴근 3시간 조회수에 매이지 않고, **주간·일간 단위로 조회가 높은 경제·증시 뉴스** 중에서 그동안 다루지 않은 주제를 고른다. 주간에 가장 핫한 내용으로 '진짜 도움이 되는 경제학' 또는 '지금 경제 상황에 맞는 행동요령'을 만든다. 출처: 네이버 랭킹뉴스(`https://news.naver.com/main/ranking/popularDay.naver?mid=etc&sectionId=101`, cp949, 언론사별 일간 랭킹)와 경제 섹션(`https://news.naver.com/section/101`). 시세·수급은 Yahoo Finance chart API(^KS11 ^KQ11 ^GSPC ^IXIC ^SOX ^VIX ^TNX KRW=X CL=F GC=F 등)와 네이버 모바일 API(`m.stock.naver.com/api/index/KOSPI/price?pageSize=60&page=N`, `.../index/KOSPI/trend?bizdate=YYYYMMDD` = 개인·외국인·기관 순매수 억원, 2010년~ 일별)로 직접 확인한다. 기사 속 통계(확률·%)는 직접 검증 전에는 '기사에 따르면'으로만 쓴다.
4. **팝업 한 장에 담을 것**: 가제(제목 후보), 오늘의 변수(수치 2~3개), 경제학 논리 한 줄, 시청자가 할 행동 한 줄, 근거 기사(언론사·제목), **겹치는 기존 영상(편 번호·제목·그 영상에서 말한 내용 한 줄)을 반드시 표기** — 겹쳐도 후보에서 빼지 말고 현철님이 보고 판단하게 한다.
5. 고른 주제로 제작 → 제작일지 기록 → 다시 3개 팝업 (반복).

## 수정 작업은 부분 수정으로 (v1.13.8, 현철님 지정: 토큰 절약)
- 영상 완성 뒤 자막 오류·부자연스러운 음성을 고칠 때는 **전체를 다시 만들거나 대본을 다시 읽지 않는다.** `python tools/fix_scenes.py projects/<폴더>/project.json "sNNN=새 문장" "sNNN:pose=놀람" --clips` 한 번으로 해당 장면만 다시 녹음·다시 그린다.
- 원리: `make_video`가 장면 클립(`projects/<폴더>/clipcache/`)과 장면별 음성을 캐시해서, 바뀐 장면만 새로 만들고 나머지는 그대로 이어 붙인다 (화질 손실 없음, 재인코딩은 바뀐 장면만).
- `--clips`는 바뀐 장면만 짧은 mp4로 `output/fix/`에 잘라 준다. **사용자에게는 그 파일만 보낸다** (영상 전체나 장면 이미지를 내가 다시 읽어 보지 않는다).
- 수정 요청을 받으면: 장면 번호/문구를 정확히 특정 → 위 명령 실행 → 결과 한두 줄 + 미리보기 파일 전송. 음성이 부자연스러운 경우는 문구 바꾸기(쉼표·숫자 풀어쓰기·낱말 교체 규칙)로 해결한다.

## 사용량 보호 규칙 (v1.13.7, 현철님 지정 2026-10-23)
- 현철님은 다른 영상 작업에도 사용량을 써야 한다. 주간 사용량이 **95%에 가까워지면, 지금 만들던 영상 하나까지만 끝내고 일시 중지**한다. 새 영상·새 기능 작업은 시작하지 않는다.
- Claude는 사용량 표시를 직접 볼 수 없다. 현철님이 사용량(예: 90% 사용됨)을 알려 주면 그 시점부터 이 규칙을 적용한다. 알려 주지 않아도 90%를 넘었다는 말을 들었다면 불필요한 이미지 열람·재탐색·긴 설명을 줄이고, 매 단계 끝에 진행 상태를 `video-studio/scripts/` 인계 문서에 적어 둔다.
- 일시 중지할 때는 지금까지 만든 것을 커밋·푸시하고, 한 줄로 "어디까지 했고 다음에 할 일"만 알린다.

## 다운로드 파일 이름·버전 (v1.7.0 — 현철님 지정, 매번 적용)
- 보내는 모든 파일은 `output/다운로드/`의 **`제목_v버전_종류.확장자`** 파일로 보낸다 (video.mp4·thumbnail.png 같은 이름으로 보내지 않기)
  - 예: `월100만원_10억_98년_실제기록_v2_영상.mp4`, `…_v2_썸네일.png`, `…_v2_자막.srt`, `…_v2_업로드정보.md`, `…_v2_제목·설명·태그.txt`
  - 제목 부분은 project.json `file_title`(짧은 이름, 없으면 제목 앞 30자)
- **수정할 때마다 버전을 하나 올린다** (v1 → v2 → v3, 썸네일만 고쳐도 묶음 전체를 새 버전으로). 예전 버전 파일은 지우지 않는다
- make_video가 렌더·`--thumb-only` 끝에 자동으로 묶음을 만든다 (`studio/package.py`). 영상이 29MB를 넘으면 압축본을 넣는다(원본은 output/video.mp4)
- 사용자에게 보낼 때 버전과 바뀐 점을 한 줄로 함께 알린다

## 품질 기준
- **썸네일 문구는 단언하는 단어로 시선을 잡는다 (현철님 지정 2026-10-23)**: '진짜', '결국', '99%가 모르는/놓치는', '절대' 같은 단정형 낱말을 후크나 2줄 문구에 넣는다. 단, 영상이 숫자로 답하는 내용에만 쓴다(영상이 답하지 않는 약속 금지는 그대로). '99%' 같은 비율 표현은 수사이며 통계가 아님을 알고 쓴다.
- 썸네일: 캐릭터(감정 표정) + 큰 숫자/화면 요소 1개 + 위 규칙의 hook 문구 2줄(상황 / 반전 질문 '?'). 제목 문장 반복 금지, 영상이 답하지 않는 약속 금지.
- 제목: 숫자 또는 모순 + 질문, 30자 안팎. 쇼츠는 `#shorts` 포함.
- 설명란: 2~3줄 요약 + 핵심 포인트 + 자료 출처·기준일 + 투자 권유 아님 문구 + 해시태그 8~15개.
- 타 채널 대본·캐릭터·썸네일을 복제하지 않는다 (구조 원리만 사용). 예시 계산은 화면에 '예시' 표기.
