# 네이버 블로그 포스트 스킬

가게 한 곳의 정보와 문체 기준을 읽고, 네이버 블로그 글 한 편을 써서 임시저장까지 합니다. 글은 발행되지 않습니다. 발행 버튼은 사람이 누릅니다.

## 준비물

- playwright-cli 스킬: 브라우저를 움직이는 부분에 필요합니다. 이 스킬 폴더 옆에 설치되어 있어야 합니다.
- 로그인된 naver.com 세션: 평소 쓰는 Chrome에서 naver.com 쿠키만 가져와 브라우저에 넣습니다.
- references/가게정보.md: 비어 있는 틀입니다. 미리 채워 두어도 되고, 비워 두면 스킬이 질문해서 채웁니다.

## 먼저 읽을 파일

| 파일 | 쓰임 |
|---|---|
| references/가게정보.md | 업종, 지역, 대표 상품, 요금, 말투. 글에 쓸 수 있는 사실의 유일한 출처 |
| references/네이버-글-구조.md | 제목 공식, 첫 문단 훅, 소제목, 사진 설명, 마무리, 해시태그 |
| references/네이버-임시저장.md | 에디터 열기부터 임시저장 확인까지 |
| references/한국어-문체.md | 해요체와 습니다체 비율, 가독성 기준, AI 흔적 패턴 |

## 가게 정보 묻기 (가게정보.md가 비어 있을 때)

가게정보.md에 아직 묻지 않은 빈 칸이 있으면 글을 쓰기 전에 아래 순서로 묻습니다. AskUserQuestion 도구가 있으면 그 도구로, 없으면 채팅으로 한 번에 한 묶음씩 묻습니다. 답을 받으면 가게정보.md에 그대로 적어 두고, 다음부터는 묻지 않습니다.

| 순서 | 묻는 것 | 묻는 방식 |
|---|---|---|
| 1 | 상호, 업종, 지역(구와 동) | 한 번에 세 칸, 자유 입력 |
| 2 | 위치 안내와 주차, 영업시간, 결제 방법 | 한 번에 세 칸, 모르면 "건너뛰기" 선택지 |
| 3 | 주요 손님 | 선택지: 직장인, 학생, 동네 손님, 직접 입력 (여러 개 선택 가능) |
| 4 | 대표 상품이나 핵심 서비스, 공개해도 되는 가격 | 자유 입력, 가격은 "적지 않음" 선택지 |
| 5 | 공간과 시설, 부가 서비스, 예약 방법, 운영 중인 이벤트 | 자유 입력, 각각 "없음" 선택지 |
| 6 | 손님이 자주 묻는 것, 가게만의 특징 한 가지 | 자유 입력, 질문은 두세 가지 |
| 7 | 손님 호칭, 꼭 쓰고 싶은 표현, 기본값 말고 더 피할 표현 | 호칭 선택지: 손님, 고객님, 이용하시는 분, 직접 입력 |
| 8 | 이번 글 주제 | 요청에 주제가 없을 때만. 자주 묻는 것에서 후보 세 개를 만들어 선택지로 제시, 직접 입력 포함 |

묻기 규칙

- AskUserQuestion으로 물을 때는 선택지를 2개에서 4개로 둡니다. 도구가 직접 입력(Other)을 자동으로 붙이므로 "직접 입력"은 선택지에 넣지 않습니다.
- 채팅으로 물을 때는 선택지를 4개 이하로 두고 마지막에 "직접 입력"을 둡니다. 자유 입력 칸은 도구가 있어도 채팅으로 묻습니다.
- 사용자가 "건너뛰기"를 고른 항목은 값 칸에 "건너뜀"이라고 적고 글에 넣지 않습니다. "건너뜀"인 칸은 다시 묻지 않습니다.
- 전화번호, 계정 ID, 이메일은 묻지 않습니다.
- 가게정보.md에 이미 값이 있는 항목은 다시 묻지 않습니다. 예외로 "쓰지 않을 표현"은 기본값이 들어 있어도 7번을 물을 때 더 피할 표현이 있는지 함께 묻고, 답을 기본값 뒤에 덧붙입니다.
- 8번 주제까지 정해지면 "가게정보.md를 채웠습니다. 글을 쓰겠습니다." 한 줄만 말하고 글쓰기로 넘어갑니다.

## 작업 순서

0. 가게 정보 확인: 가게정보.md를 읽습니다. 아직 묻지 않은 빈 칸이 있으면 위 "가게 정보 묻기"를 먼저 합니다.
1. 주제 확정: 요청에 주제가 있으면 그대로 씁니다. 없으면 가게정보.md의 "자주 쓰는 주제"에서 고르고, 그것도 없으면 묻기 8번으로 정합니다. 글 한 편에는 주제 하나만 둡니다.
2. 게이트 1 구조: 제목, 훅 패턴, 소제목, 사진 자리를 정합니다.
3. 게이트 2 초안: 구조대로 본문을 씁니다.
4. 게이트 3 사실 대조: 본문의 모든 사실을 가게정보.md와 맞춰 봅니다.
5. 게이트 4 문체: 한국어-문체.md 기준으로 고칩니다.
6. 자기 점검: 아래 점검표를 저장 직전에 한 번 돌립니다.
7. 임시저장과 게이트 5: 네이버-임시저장.md 순서대로 입력하고, 저장 뒤 다시 열어 확인합니다.

## 게이트

게이트는 순서대로 통과합니다. 앞 게이트를 통과하지 못하면 다음으로 넘어가지 않습니다.

| 게이트 | 하는 일 | 통과 기준 |
|---|---|---|
| 1 구조 | 제목, 훅, 소제목, 사진 자리 확정 | 제목이 "지역 + 업종 + 주제" 공식에 맞음. 느낌표 0개에서 1개. 소제목 3개에서 5개. 소제목마다 사진 자리 1개. 훅 패턴 하나를 골랐음 |
| 2 초안 | 본문 작성 | 공백 포함 1,200자에서 1,800자(해시태그 줄 제외). 첫 문단에 지역이나 업종 키워드 1회. 소제목 아래 2문단에서 3문단. 마지막 문단이 마무리 패턴(이용 방법, 문의 방법, 찾아오는 길) 중 한 가지로 끝남 |
| 3 사실 대조 | 사실 문장마다 가게정보.md 출처 행 확인 | 숫자, 시간, 가격, 시설, 서비스 이름이 모두 가게정보.md에 있음. 없는 문장은 삭제했거나 확인 질문으로 돌렸음 |
| 4 문체 | 한국어-문체.md 적용 | 어미 비율 5:5 안팎(한쪽 70% 이하). 문장 50자 이내. 문단 3문장에서 4문장. AI 흔적 패턴 0건. 금지 부호 0건 |
| 5 임시저장 확인 | 저장 뒤 재열기 | "저장" 버튼 옆 임시저장 글 수가 저장 전보다 1 많음. 다시 연 글의 제목, 본문, 해시태그 줄이 그대로임. 발행 상태가 아님 |

### 수정 규칙

- 게이트에서 막히면 그 게이트의 문제만 고쳐 다시 검사합니다.
- 같은 게이트는 최대 2번까지 고칩니다.
- 2번 고쳐도 통과하지 못하면 문제가 된 문장을 글에서 빼고, 이유를 보고에 적습니다.
- 문체를 고치다가 사실이 바뀌면 게이트 3부터 다시 합니다.
- 게이트 5가 실패하면 중복 저장을 피하려고 "저장" 버튼 옆 임시저장 글 수를 먼저 확인한 뒤 다시 시도합니다.

### 사실 대조표

게이트 3에서 머릿속으로 넘기지 말고 표를 만들어 확인합니다. 표는 보고에만 쓰고 글에는 넣지 않습니다.

| 본문 문장 | 출처 행(가게정보.md) | 결과 |
|---|---|---|
| 예: 영업시간은 매일 오전 10시부터입니다 | 영업시간 | 일치 |

결과가 "없음"인 문장은 삭제합니다. 가게정보.md에 비어 있거나 "건너뜀"인 항목은 추측하지 않습니다.

## 자기 점검표 (저장 직전)

| 점검 | 기준 |
|---|---|
| 제목 | 지역, 업종, 주제가 모두 있고 25자 안팎 |
| 첫 문단 | 훅 패턴 하나로 시작하고 키워드가 1회 들어감 |
| 첫 문단 3문장 | 누가 어떤 상황에서 읽는 글인지 밝힘 |
| 소제목 | 3개에서 5개, 서로 내용이 겹치지 않음 |
| 사진 설명 | 모든 사진 자리에 짧은 설명 한 줄 |
| 사실 | 대조표에 "없음"이 0건 |
| 호칭 | 가게정보.md의 손님 호칭으로 통일 |
| 금지 표현 | 최상급, 다른 가게 비교, 과장어 0건 |
| 마무리 | 마무리 패턴(이용 방법, 문의 방법, 찾아오는 길) 중 한 가지, 요약과 다음 글 예고 없음 |
| 해시태그 | 3개에서 5개, 본문 마지막 줄 |
| 개인 정보 | 전화번호, 계정 ID, 이메일 0건 |

## 사진 자리

| 상황 | 처리 |
|---|---|
| 사용자가 사진 폴더를 알려 줌 | 표시한 사진 자리마다 그 폴더의 사진을 에디터에 올립니다. 글 내용과 맞는 사진을 고르고, 없으면 그 자리는 텍스트로 남깁니다. |
| 사진 폴더를 알려 주지 않음 | 사진 자리를 "[사진: 설명]" 텍스트로 남기고 사진은 올리지 않습니다. |

## 지킬 규칙

- 발행, 예약 발행, 공개 설정 변경은 하지 않습니다.
- 에디터의 태그 칸은 건드리지 않습니다. 해시태그는 본문 마지막 줄에만 씁니다.
- 가게정보.md에 없는 사실은 쓰지 않습니다. 값을 모르면 지어내지 말고, 글을 쓰기 전이면 묻고, 쓰는 중이면 글에서 빼고 보고에만 적습니다.
- 다른 가게나 다른 업체와 비교하는 문장은 쓰지 않습니다.
- 최상급 표현("최고", "유일", "가장")은 쓰지 않습니다.
- 전화번호, 계정 ID, 이메일은 글에 넣지 않습니다.
- 브라우저는 naver.com 쿠키만 씁니다. 쿠키 값은 출력하지 않고, 작업이 끝나면 쿠키 파일을 지웁니다.
