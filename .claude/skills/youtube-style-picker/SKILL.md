# 주제 → 스타일 고르기 → 제작

## 1. 고르기
1. `docs/스타일_라이브러리.md`의 "고르는 법" 표로 스타일을 정한다. 고른 이유는 보고에 한 줄로 적는다.
2. 맞는 스타일이 없으면 만들지 않고 정확히 이렇게 말한다.
   > 또 다른 유튜브 영상 샘플을 올려줘
   - 왜 안 맞는지 한 줄 덧붙인다(예: "요리 실사 영상이라 지금 스타일 3개로는 맞지 않습니다").
3. S3 screen이 맞는데 화면 녹화가 없으면, 화면 녹화를 요청하거나 S2로 개념 편을 먼저 만들자고 제안한다.

## 2. 기획안을 받았을 때
- 기획안의 사실(도구 기능, 숫자)은 **1차 자료 원문으로 확인**한다(SCR-1).
- 틀리거나 출처 없는 내용("3분 만에", "3배")은 빼거나 고쳐 쓰고, 바꾼 점을 대본 머리 주석과 보고에 적는다.
- 위험한 활용(남의 소프트웨어 무단 분석, 보안 정책 위반)은 빼고, 원래 도구의 사용 원칙을 화면에 원문 그대로 보여 준다.

## 3. 제작
- 대본: `projects/<slug>.yaml`에 `style: paper|neon`을 적는다. 장면 종류는 스타일별 html 머리말에 있다.
- 순서: `--stills`로 그림 확인 → 빌드 → 자체 검수(⚠ 0 또는 설명) → 파일럿 컨펌 → 롱폼. 자세한 절차는 `editorial-video` 스킬.
- 목소리
  - 스타일마다 `style.yaml styles.<이름>.voice`에 정해져 있고, Voicebox(현철님 PC)에서 만든다.
  - PC가 연결되어 있지 않으면 `--stand-in-voice`로 편집만 검수한다. 이렇게 만든 파일은 "임시 목소리"라고 밝히고 배포하지 않는다.

## 4. 새 샘플 학습 (링크를 받으면)
1. `yt-dlp --skip-download`로 메타데이터를, `-f sb0`로 스토리보드를, `--write-auto-subs --sub-langs ko`로 자막을 받는다. 차단되면 우회하지 않는다.
2. 측정한다: 밝은·어두운 화면 비율, 5초 간격 변화량, 강조색, 음절/초, 분당 쉼, 첫 25초 문장.
   - 측정 코드는 `docs/스타일_라이브러리.md` 작성 때 쓴 것과 같고, 기존 측정값과 비교해 둔다.
3. 스토리보드를 Read로 직접 보고 화면 구성, 자막, 장면 종류를 적는다.
4. 기존 스타일과 같으면 그 스타일에 샘플로 추가한다. 다르면 S4로 새로 등록하고, `style.yaml styles:`와 장면 html을 만든다.
5. 라이브러리 표의 "고르는 법"도 갱신한다.
