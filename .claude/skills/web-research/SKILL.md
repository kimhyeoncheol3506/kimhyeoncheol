# Web Research (무료 딥리서치)

gpt-researcher의 planner → executor → publisher 구조를 Claude Code 기본 도구(WebSearch, WebFetch)만으로 재현한 스킬이다. OpenAI·Tavily 등 유료 API 키가 필요 없다.

## 언제 쓰나
- 영상·쇼츠 대본에 들어갈 사실·숫자·순위를 모을 때 (맛집 TOP10, 경제 이슈, 상품 비교 등)
- 시장조사, 경쟁사 정리, 업계 동향 보고서
- 이미 쓴 대본·자막의 사실관계 확인(팩트체크)

## 절차

### 1. 계획 (Planner)
- 조사 목적과 최종 산출물(대본 소스? 보고서? 표?)을 한 줄로 정리한다.
- 주제를 **3~6개의 하위 질문**으로 쪼갠다. 서로 겹치지 않게, 각 질문이 독립적으로 검색 가능하게.
- 기준 날짜를 확인한다(`date`). "최신", "올해" 같은 표현은 실제 연도로 바꿔 검색한다.

### 2. 수집 (Executor)
- 하위 질문마다 WebSearch를 **따로** 실행한다. 서로 의존하지 않는 검색은 한 번에 병렬로 보낸다.
- 검색어는 짧게(2~6단어). 한국 주제는 한국어로, 해외 주제는 영어로도 한 번 더 검색한다.
- 결과가 빈약하면 표현을 바꿔 재검색한다. 같은 검색어를 반복하지 않는다.
- 핵심 근거가 될 페이지는 WebFetch로 본문을 읽는다(스니펫만으로 숫자를 쓰지 않는다).
- 출처 우선순위: 공식 기관·기업 발표·공시 > 주요 언론 > 전문 매체 > 블로그·커뮤니티(보조로만).
- 상충하는 정보가 나오면 양쪽 출처를 모두 기록하고, 더 최신·더 1차적인 쪽을 채택한다.

### 3. 정리 (Publisher)
`research/<YYYYMMDD>-<주제-슬러그>.md` 파일로 저장한다. 형식:

```markdown
# <주제>
- 조사일: YYYY-MM-DD
- 목적: <한 줄>

## 핵심 요약
- 3~5줄. 바로 대본·보고서에 쓸 수 있는 결론.

## 하위 질문별 정리
### Q1. <질문>
- 사실 1 [1]
- 사실 2 [2]

## 숫자·팩트 표 (해당 시)
| 항목 | 값 | 기준일 | 출처 |

## 불확실·상충 사항
- <확인 안 된 것, 출처 간 차이>

## 출처
1. [제목](URL) — 매체, 날짜
```

## 규칙
- 모든 숫자·순위·인용에는 출처 번호를 단다. 출처 없는 문장은 "추정"으로 표시한다.
- 원문을 길게 복사하지 않는다. 인용은 한 출처당 1회, 15단어 미만. 나머지는 요약해서 쓴다.
- 기사 사진·인물 사진은 내려받지 않는다. 자료화면이 필요하면 출처 URL만 기록한다.
- 검색으로 확인 못 한 내용은 기억으로 채우지 않고 "확인 필요"로 남긴다.
- 조사가 끝나면 사용자에게 핵심 요약 3줄과 파일 경로만 알려준다.

## 대본 작업과 연결
- 영상 프로젝트에서 호출된 경우, 보고서의 "핵심 요약"과 "숫자·팩트 표"를 대본 작성 단계의 입력으로 쓴다.
- 자막에 들어가는 숫자는 반드시 표의 값과 일치시킨다.
