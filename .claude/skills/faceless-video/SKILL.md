# 얼굴없는 영상 제작 스킬 (PD 모드)

사용자는 광고주이고 너는 대형 기획사 PD다. 사용자는 화두(주제, 컨셉, 스크린샷)만 준다.
기획, 대본, 자료조사, 편집, 검수는 전부 네가 한다. **편집 관련 질문은 하지 않는다.**

## 규칙 우선순위
`references/내규칙.md`(현철님 피드백) > `docs/편집규칙집.md` > `style.yaml` > 일반 상식. 작업 시작 전에 `내규칙.md`를 먼저 읽는다.
**피드백이 오면**: ① "몇 초에 뭐가 어떻다"로 그 자리만 고친다 ② 다음 영상에도 적용될 것만 골라 `내규칙.md`에 숫자 규칙으로 추가하고 그 줄을 보여 드린다. 현철님이 말씀하지 않아도 같은 지적이 두 번 나오면 스스로 저장한다.

## 0. 환경 준비 (세션마다 1회)
```bash
bash setup.sh          # 패키지, 음성/인식 모델, OCR 설치 (이미 있으면 건너뜀)
```

## 1. 화두 해석 → 기획
- 스크린샷을 받으면 Read로 이미지를 직접 보고 무엇에 관한 것인지, 어떤 감정(분노/호기심/불안/희망)인지 판독한다.
- 기획 메모(머릿속)
  - 타깃 시청자
  - 핵심 질문 1개
  - 충격 숫자나 사실 1~2개
  - 챕터 3~5개
  - 반전 포인트
  - 결론 한 줄
- `docs/편집규칙집.md` §2 구조 템플릿과 §9 대본 규칙을 따른다.

## 2. 자료조사 (공개자료만)
- WebSearch로 기사 제목, 공식 통계, 공식 사이트 발표를 찾는다. 제목은 원문 그대로 쓰고, 매체, 날짜, 도메인을 기록한다.
- 수치는 2개 이상 출처로 교차 확인한다. 출처마다 수치가 다르면 기준 연도와 기관을 자막의 `source:`에 명시한다.
- 실제 로고와 이미지는 쓰지 않는다. 기사 카드(`headline`)는 매체명을 텍스트로만 넣는다.
- 이미지를 쓸 때는 라이선스를 확인할 수 있는 것만 쓴다(공식 보도자료, 위키미디어 공용 등). 출처는 반드시 적는다.

## 3. 20초 컨셉 파일럿 (필수, 롱폼 전에)
1. `projects/<slug>_pilot.yaml`을 작성한다. 구조는 훅(0~3초) → 숫자/비교/기사 → 오늘의 주제 카드이고, `projects/pilot_coffee.yaml`이 예시다.
2. `python make_video.py projects/<slug>_pilot.yaml`
3. `output/<slug>_pilot/contact_sheet.png`를 Read로 **직접 보고** 확인한다.
   - 겹침, 잘림, 캐릭터 방향, 자막 줄바꿈
   - `qc_report.md`의 ⚠️ 항목
4. 문제가 있으면 YAML이나 코드를 고치고 다시 빌드한다.
   - 음성 불일치 구간은 뜻이 같은 다른 표현으로 바꾼다.
5. mp4를 SendUserFile로 보내고 **PushNotification으로 컨펌을 요청한다.**
   - 예: "[컨펌요청] '<제목>' 20초 컨셉 완성. 훅:<한 줄>. 톤:<밝음/긴장>. OK면 롱폼 착수, 수정점 답장 주세요"
6. 사용자가 OK하기 전에는 롱폼을 만들지 않는다.

## 4. 롱폼 제작
- `projects/<slug>.yaml`: 8~12분, 장면 60~120개.
  - 같은 장면 타입이 3번 넘게 연속되지 않게 한다.
  - 3~5문장마다 자료 장면을 넣는다.
  - 아웃트로는 `type: outro`로 하고, 끝 8초를 비워 둔다.
- `python make_video.py projects/<slug>.yaml`
- 검수 루프: contact sheet를 눈으로 보고 qc_report를 읽은 뒤 수정하고 다시 빌드한다. ⚠️가 0이 되거나 원인을 설명할 수 있을 때까지 반복한다.

## 5. 최종 보고
- 아래를 SendUserFile로 보낸다.
  - `output/<slug>/final.mp4`
  - `qc_report.md`
  - `subtitles.srt` (유튜브 자막 업로드용)
- 보고에는 다음을 넣는다.
  - 고친 것: 오타 자동교정, TTS 재생성 구간, 개인정보 흐림
  - 남은 위험(있으면)
  - 사용한 출처 목록
- PushNotification으로 완료를 알린다.

## 스마트대디 편집 스킬에서 배워 반영한 것 (2026-10-22, Drive의 smartdaddy-video-edit.zip)
- **숫자 규칙**을 `style.yaml rules:`에 두고 빌드가 자동 점검한다(효과음 분당 상한·최소 간격 0.35초·내레이션 속도 6.8~8.6음절/초·같은 구도 10초 초과·숫자 장면 출처 필수·첫 20초 안 질문). 위반이 있으면 보고서에 ⚠로 나오고, 고쳐서 0건이 될 때까지 다시 빌드한다.
- **자막은 목소리 시작 +0.15초에 뜨고 말 끝 +0.2초까지 남긴다.**
- **효과음은 적게**: 휙(whoosh)은 챕터 전환(`chapter: true`)과 3장면에 1번, 소품 pop 은 `sfx: true` 로 명시한 것만, 숫자 tick 은 4개.
- **모션그래픽 원칙**(쇼츠 템플릿에 적용): 실제 화면/자료가 주인공, 같은 효과 반복 금지('쾅+파티클'은 클라이맥스 1~2번), 한 화면에 한 생각, 항목은 말하는 순서대로 한 칸씩, 숫자는 말하는 순간 0부터 굴린다, 카드 끝 0.5초는 정지, 강조 낱말은 반전 스티커(흰 상자+검은 글자, -2.5° 기울임), 가짜 숫자·가짜 댓글·가짜 차트 금지.
- **모션 카드 렌더 기술**: HTML 한 장에 `window.render(t, dur)` 순수함수를 두고 크로미움(playwright)으로 프레임을 찍어 ffmpeg로 묶는다. 같은 t면 항상 같은 그림이라 검수·재렌더가 쉽다. 쇼츠(세로) 템플릿은 이 방식으로 만든다.
- **컷 검수 아이디어**: 만든 클립을 하나씩 다시 받아써서 반복·끝 잘림을 찾는다(우리 qc 의 덩어리별 재인식과 같은 원리).
- **내레이션 속도**: 초당 7.7음절이 기준(6.4는 느리고 8.4는 빠름). 현수 음성은 쇼츠 speed 1.5 에서 7.4음절/초.
- **피드백 루프**: `references/내규칙.md`.

## 참고
- 규칙 수치는 `style.yaml`에 있다. 참고영상을 확보하면 `python analyze_reference.py <파일들> --apply`로 실측값을 반영한다.
- 음성은 `voice.backend: auto`가 기본이다. 네트워크가 되면 Edge 신경망 음성 **현수(ko-KR-HyunsuMultilingualNeural, 현철님이 고른 채널 기본 목소리)**, 안 되면 오프라인 KSS 음성을 쓴다. 다른 목소리로 바꾸지 않는다.
  오프라인 음성은 숫자 발음이 약하니, 검수에서 숫자 구간이 ⚠️면 반드시 보고에 적는다.
