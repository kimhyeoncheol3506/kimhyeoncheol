# 최종본 세트 내보내기 (PUB-01·02·03)

현철님 요청(2026-11-04): "유튜브 설명란에 적게 제목, 설명란(관련사이트, 깃허브 주소 등), 해시태그, 출처… 썸네일도 세트로… 생성파일의 이름을 영상주제에 맞게 버전관리하면서… 항상 적용".

## 세트 = 파일 3개 + 기록 1개
```
release/<주제>/<주제>_v4.mp4          최종 영상
release/<주제>/<주제>_v4_유튜브.txt    제목(+후보) · 설명란(요약·챕터·관련 사이트·깃허브·참고한 영상·출처·해시태그) · 해시태그 · 출처
release/<주제>/<주제>_v4_썸네일.jpg    1920x1080, 2MB 이하
release/<주제>/버전기록.md             버전 · 날짜 · 길이 · 검수 결과 · 바뀐 점
release/<주제>/<주제>_v4_폰용.mp4         폰에서 보기용 720p 사본(보낼 때는 이것도 함께)
```
- 빌드(`editorial/make_editorial.py`, `shorts/make_short.py`)가 끝나면 자동으로 만든다: `facetube/youtube_txt.py` → `facetube/thumbnail.py` → `facetube/release.py`.
- 바뀐 점은 `--note "훅 첫 줄 앞당김"` 또는 대본 `release_note:` 로 적는다. 안 적으면 기록이 '-' 로 남으니 꼭 적는다.
- 세트 중 하나만 바뀌어도(썸네일 글자만 고쳐도) **새 버전으로 세트 전체**를 내보낸다. 버전이 어긋난 파일끼리 섞이지 않게.
- 20초 샘플·`--stills`·`--stand-in-voice` 는 최종본이 아니다(임시목소리는 파일 이름에 `_임시목소리`).
- mp4 는 git 에 올리지 않는다(.gitignore). txt·jpg·버전기록.md 는 올린다.

## 대본 yaml 에 채울 칸 (새 영상을 쓸 때 처음부터)
```yaml
name: AI브라우저_어사이드_사용법     # 파일 이름이 되는 주제(한글 가능, 띄어쓰기는 _ 로)
title: "..."                         # 100자 이하
title_alt: ["후보 제목 1", "후보 제목 2"]
summary: |
  ...
tags: ["#..."]                       # 15개 이하(16개부터 유튜브가 전부 무시)
links:   [{name: "공식 사이트", url: "https://..."}]       # 관련 사이트
github:  [{name: "저장소", url: "https://github.com/..."}]  # 확인된 주소만. 없으면 칸을 빼고 지어내지 않는다
references: [{name: "참고한 채널", url: "https://youtu.be/..."}]
sources: [...]                       # 출처(원문을 연 것은 verified: true)
thumbnail:
  bg: ../assets/thumbs/<slug>_bg.png # 글자 없는 AI 그림
  tag: "작은 띠 글자"
  line1: "첫 줄(흰색)"
  line2: "[[강조]] 둘째 줄"          # [[ ]] = 강조색
  accent: "#FF8A3D"
```

## 썸네일 그림 만들기
- 모양 두 가지(대본 `thumbnail.layout`):
  - 기본(그림형): 위 3D 일러스트(AI, 글자 없음) + 아래 굵은 두·세 줄 제목.
  - `layout: tiles`(2026-11-04 현철님 본보기 'Git과 GitHub'): 어두운 바탕 · 위쪽 가운데 제목(둘째 줄 [[강조]]는 형광 상자) · 아래 반짝이는 검은 앱 타일 줄 + 뒤에서 빼꼼 보는 원본 마스코트. 그림 생성 없이 만들어 크레딧이 들지 않는다. `tiles: [folder, commit, branch, cloud, merge, save, people]` 로 아이콘을 고른다(실제 로고 대신 직접 그린 아이콘).
- 라벨(`tag`)은 빼도 된다(현철님: 깃허브 썸네일에서 삭제 요청).
- 본보기 모양: 위쪽 3D 일러스트(귀여운 캐릭터 + 화면/주제 물건), 아래쪽 아주 굵은 두 줄 제목, 검은 테두리.
- 그림은 AI 로 **글자·로고·워터마크 없이** 만든다(프롬프트에 "no text, no letters, no logos, no watermark", 아래 35%는 비워 두기). 글자는 thumbnail.py 가 폰트(Pretendard Black)로 얹는다.
- 다른 채널 캐릭터·실제 회사 로고를 베끼지 않는다. 워터마크가 찍힌 그림은 쓰지 않는다(지우지도 않는다).
- 크레딧이 드는 생성은 **먼저 현철님께 가격을 말하고 묻는다**. 2026-11-04: OpenArt 무료는 워터마크가 찍혀 못 씀 → Fish Audio `gpt-image-2.5-sunburst` 2K high(1,896 크레딧)로 만듦.
- 받은 그림은 `assets/thumbs/<slug>_bg.png` 에 두고 git 에 올린다(다시 만들 때 재사용).
- 만든 썸네일은 반드시 열어 보고 확인: 글자 잘림·그림과 겹침·작은 화면에서 읽힘.

## 보낼 때
1. 버전기록.md 의 새 줄과 검수 결과를 확인한다.
2. 세트 3개를 현철님께 보낸다(영상은 render, txt 는 attach, 썸네일은 render).
3. 보고: 버전, 주제 이름, 바뀐 점, 남은 검수 경고, 사람 귀로 확인할 곳.

## 긴 빌드를 돌릴 때 (2026-11-05)
- 클라우드 세션은 내가 턴을 끝내고 추적 중인 백그라운드 작업이 없으면 쉬다가 컨테이너가 회수돼 빌드가 멈춘다.
- 그래서 빌드를 띄운 뒤에는 **반드시 `run_in_background` 로 "끝날 때까지 기다리기" 작업을 함께 걸어 둔다**(최대 2시간, 끝나면 다시 건다). send_later 점검은 보조용.
- 빌드가 도는 동안에는 `--stills` 확인 렌더도 돌리지 않는다(2026-11-07: 아르곤 그림 확인이 뮤즈 빌드의 Qwen 일꾼을 메모리 부족으로 죽임). `--out` 을 바꾸면 TTS 캐시도 새로 만들므로, 확인 렌더는 원래 `_work/tts` 를 복사해 두고 빌드가 없을 때만.
- 두 빌드는 동시에 돌리지 않는다(Qwen 일꾼 약 8~10GB). 다음 빌드는 대기 스크립트로 줄 세운다.
